# AI IDE Studio — 设计愿景

## 核心问题

当前 AI 编程工具（如 Cursor、GitHub Copilot）依然是"人管 N 个会话"的模式：
- 每个任务要自己开会话、记住在哪个会话里做的
- 会话之间无法溯源，上下文丢失
- AI 只在被问到时才工作，没有自主性

## 我们的答案：以任务为中心的 Agent 协作

不是"人开会话让 AI 做事"，而是：
- **任务是原子单位** — 人创建任务或 Agent 自主发现任务
- **Agent 是持久实体** — 有记忆、有专长、能自主工作
- **Session 是工作记录** — 不是人管理的"对话窗口"，而是 Agent 执行任务时自动产生的记录

## 四个核心实体

```
Project ─┬─ Agent（持久化智能体）
         │    └── Session（工作记录）
         └── Task（任务单元）
              └── 关联到多个 Session
```

### Project（项目）
- 一个项目 = 一个代码仓库 / workspace
- 一次只工作在一个项目中（单项目工作模式）
- 通过顶栏切换器切换项目

### Agent（智能体）
- 持久化的 AI 实体，不因会话结束而消失
- 有类型（Dev / Test / Ops / Security / PM）
- 有持久记忆（通过 RAG 检索，不塞 prompt）
- 有自主权限等级（L0-L4）
- Agent 模板全局共享，实例绑定到项目

### Task（任务）
- 原子化工作单元
- 来源：人手动创建 / Agent 自主发现 / 事件触发 / 定时触发
- 没有"进度百分比"——AI 写代码不存在线性进度
- 用**阶段描述**代替：当前在做什么、处于什么状态

### Session（会话/工作记录）
- Agent 执行任务时自动产生
- 独立的对话上下文，**绝对不混用**
- 完成后归档，不会"爆炸"
- 可以基于模板派生（预设好的 System Prompt + 基础上下文）

## 记忆架构

```
┌─────────────────────────────────┐
│    System Prompt（稳定）         │ ← 前缀缓存友好
├─────────────────────────────────┤
│    Agent 角色定义（稳定）        │
├─────────────────────────────────┤
│    对话历史（append-only）       │ ← 增量缓存
├─────────────────────────────────┤
│    recall_memory() 检索结果     │ ← 动态注入，不影响前缀
└─────────────────────────────────┘
```

- Agent 级持久记忆 = 可检索知识库（RAG），不放进 prompt 前缀
- Session 级上下文 = 独立对话历史，不混用
- 多任务时 System 只显示任务概况，详细上下文通过 tool call 拉取
- 这样动态记忆更新不会导致前缀缓存失效

## Agent 自主性等级

| 等级 | 描述 | 举例 |
|------|------|------|
| L0 | 仅监听 | 静默观察代码变更 |
| L1 | 通知 | 发现问题后通知人 |
| L2 | 建议 | 提出修复方案供人选择 |
| L3 | 先做后报告 | 自主修复低风险问题 |
| L4 | 完全自主 | 自主决策和执行 |

## 与现有工具的区别

| | 传统 IDE + Copilot | Cursor | AI IDE Studio |
|---|---|---|---|
| AI 角色 | 补全工具 | 对话助手 | 自主协作者 |
| 管理方式 | 人管代码 | 人管会话 | 系统管任务 |
| 持久性 | 无 | 单会话 | Agent 永久 |
| 多任务 | 手动切换 tab | 手动开会话 | Agent 并行处理 |
| 自主性 | 无 | 被动响应 | 主动感知+执行 |
