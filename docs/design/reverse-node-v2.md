# 客户端远程执行与双向文件传输方案 v2

日期：2026-09-07。用户已确认隔离开发；部署需另行授权。

本方案在远程执行功能范围内取代 `reverse-node-implementation-plan.html` 的行为定义；旧文件保留供追溯。具体改动与测试清单见 `docs/superpowers/plans/2026-09-07-reverse-node-v2.md`。

## 1. 目标与范围

服务端运行 AI，日常开发、命令和文件操作默认继续在服务器执行。只有需要排查 PC 或访问 PC 文件时，AI 才显式调用设备工具，在指定 Windows Electron 客户端执行该次操作；结果回到原会话后，普通工具仍操作服务器。不切换整个会话的执行位置，不保存会话目标设备绑定。

首版交付：Windows Electron remote 模式、设备配对与停用、两个 AI 工具、同步短命令、后台作业、双向文件传输、作业状态与取消、必要的操作记录。

不要求客户端安装或运行大模型；使用系统已有 Windows PowerShell 5.1，优先使用已安装的 pwsh，不自动安装 Python 或其他工具。macOS/Linux 执行器以后单独验收。

首版不做逐条执行审批和客户端目录白名单，沿用用户已确认决定。命令以桌面程序当前操作系统用户身份执行，不自动提权。首次启用时说明“允许此服务端 AI 操作本机文件和运行命令”，并提供本地停用和服务端解绑。

只有用户明确启用远程执行的 PC Electron 桌面端注册为执行节点。手机 APP、手机浏览器和普通网页不注册设备，不注入手机设备身份，不出现在 device_list 中。用户从手机发消息，仍可让服务器 AI 调用已授权 PC；聊天入口与执行目标无关。首版不用新增 APP 页面或手机执行模块。

## 2. 用户操作与设备选择

1. Electron remote 模式连接服务器后，用户在连接设置中启用“允许 AI 操作本机”。默认关闭，不因升级客户端而自动授权。
2. 已有 owner 认证用于创建短期配对授权；Electron 自动用该授权换取独立设备凭证并主动连接 Gateway。首版不增加手工输入配对码界面。
3. 设置页显示设备名、系统、在线状态、最后连接时间，以及停用/解绑操作。设备凭证按服务器身份隔离保存，不跨 remoteOrigin 复用。
4. 用户日常发消息、使用普通工具，无需选择设备，继续在服务器执行。会话不新增设备选择控件，不持久化默认目标，也不从消息发送端隐式注入目标设备。
5. 用户要求排查 PC 时，AI 调用 device_list，根据用户点名和设备信息确定目标；“这台电脑”无法唯一确定时询问一次。不得默认选列表第一台。
6. invoke_device_command 每次必须显式携带 deviceId，只影响这次远程操作。缺少 deviceId 返回参数错误，目标离线返回 device_offline；不自动换机，也不退回服务器执行这条命令。

设备列表包含已授权 PC 的机器名、系统、在线/离线状态和 `isCurrentDevice`，不包含会话默认执行设备。当前设备是本轮用户消息的来源 PC：Electron 主进程签名绑定消息/会话/时效，服务端验证后随消息排队，批次结束清除；混合来源、手机/浏览器/自动消息不猜测设备。项目、Agent、会话身份来自工具上下文，用于记录调用归属，不用于选择执行机器。

设备首版属于当前 Studio owner 实例，不宣称已有多账号隔离。多个项目可使用同一已授权设备，但作业结果与文件必须保留项目、会话归属；访客无设备管理或执行权限。若未来引入多账号，需再增加真实身份贯穿，不能只给表加 user_id。

## 3. 端到端架构

```text
原会话中的服务端 AI
  -> 普通 shell/read/write -> 服务器（默认）
  -> device_list -> 发现已授权 PC
  -> invoke_device_command(deviceId, ...) -> Gateway -> 指定 PC
  <- 远程结果/作业状态/文件位置 <- Gateway <- 指定 PC
```

客户端主动建立 WS 命令连接并发起 HTTP 文件请求，无须客户端入站监听。HTTPS 对应 WSS；HTTP 对应 WS，遵循现有服务器连接配置。外网部署推荐 TLS，不额外禁止现有 HTTP 内网部署。

节点连接器归 Electron 主进程管理，与聊天渲染页面生命周期独立。聊天页面刷新不重建节点；切换服务器或本地/远程模式时结束旧连接并清空旧连接内待发命令。Gateway 的节点 WS 独立路由，不依赖普通聊天 WS 是否部署在 realtime 独立进程。

原生 shell/read/write 工具仍操作 AI runtime 所在服务器。设备工具操作明确的客户端；每次结果包含 deviceId、设备名和执行目录，文件结果明确哪端路径。

## 4. 两个 AI 工具

### device_list

无必填参数。返回已授权 PC 的 deviceId、机器名、系统、可用 shell、默认 shell 和在线状态。返回客户端用户目录和桌面/下载/日志目录等已探测位置，避免 AI 猜测用户名或假设桌面一定在 `~/Desktop`。不返回手机，不返回默认执行目标。

### invoke_device_command

通用字段：`type` 和 `deviceId` 每次必填，包括作业查询和取消。具体分支由服务端严格校验，拒绝相互矛盾的参数。不从会话、项目或当前消息发送端推断设备。

| type | 参数 | 行为 |
| --- | --- | --- |
| shell | command 必填；shell、cwd、timeoutSeconds、background、outputEncoding 可选 | 在客户端执行命令 |
| file.upload | localPath 必填 | 客户端文件上传 Gateway，始终作为后台作业 |
| file.download | serverPath 或 fileId 二选一；localPath 必填；overwrite 可选 | Gateway 文件下载到客户端，始终作为后台作业 |
| job.status | jobId 必填；cursor 可选 | 返回当前状态、分页新增日志和最终结果 |
| job.cancel | jobId 必填 | 请求取消，返回是否确认停止 |

作业查询与取消根据 jobId 找原作业，并校验所传 deviceId 与原作业设备一致，不一致则拒绝，不能借此更换目标。除明确授权的 owner 管理页面外，工具只能查询/取消本会话作业，避免跨会话误操作。

短命令默认等待最多 5 秒，已完成返回合并输出 output 和 exitCode；尚未完成返回 jobId 和 queued/running，不能把等待接受称为已运行。`background=true` 在客户端确认接受后尽快返回 jobId，未确认时同样至多等待 5 秒。timeoutSeconds 是执行寿命，默认 60 秒、上限 600 秒，与工具等待时间分开；后台同样遵守明确寿命，不表示无限运行。

命令退出码非零是执行失败，不混同通信失败。工具文案明确不需要逐条确认，禁止把命令发送到目标不明的设备。

工具描述必须明确：普通操作默认在服务器；仅当用户要求操作 PC 或已授权任务需要访问该 PC 时使用设备工具。设备工具提供给服务端 AI，与用户通过 PC 还是手机聊天无关；“手机不注入设备”不代表从手机发消息时禁用对 PC 的远程调用。

示例：

```json
{"type":"shell","deviceId":"dev-office","command":"Get-Content -LiteralPath 'D:/logs/client.log' -Tail 100","shell":"powershell"}
```

```json
{"type":"file.upload","deviceId":"dev-office","localPath":"D:/logs/diagnostics.zip"}
```

```json
{"type":"file.download","deviceId":"dev-office","serverPath":"reports/diagnosis.md","localPath":"D:/Reports/diagnosis.md"}
```

```json
{"type":"job.status","deviceId":"dev-office","jobId":"job-diagnostics"}
```

## 5. 作业与异常语义

所有执行先生成 jobId 并登记，再发送；节点接受后返回确认。状态包含 queued/running/succeeded/failed/cancel_requested/cancelled/timed_out/unknown。

- 发送前已离线：不执行，立即失败。
- 指令已发送但确认丢失：标记 unknown，不能称“未执行”。重连查询原 jobId，不自动新建或重跑命令。
- 同一 jobId 重发：节点持久化接收记录并去重，不启动第二个子进程；结果重复上报幂等。
- AI 收到 unknown 时：先查询既有作业，不盲目重新提交修改类命令。新工具调用默认是新操作；不承诺跨不同 jobId 自动语义去重。
- Gateway 重启：内存等待结束，持久化作业与节点对账；不丢掉已经执行的事实，不自动重放未知作业。
- 客户端进程退出或整机重启：记录并在下次连接对账；没有可靠完成信息则保留 unknown。
- job.cancel：先标记取消请求，客户端确认已停止后才标 cancelled。离线时不能报告取消成功。
- timeout：节点负责终止其拥有的进程树；kill 未确认时仍不能声称进程已经停止。取消不等于回滚已写文件。
- 并发：每设备默认最多 2 个执行作业、1 个传输作业；超过返回 busy，不形成无限队列。同一路径的下载互斥。

退出桌面程序/本地停用时停止受管作业；首版不保证退出后继续运行，也不宣称 detached 子进程天然可管理。用户关窗口进入托盘是否继续沿用当前桌面生命周期，真正退出明确断连并执行清理。

## 6. 文件传输闭环

### 客户端上传

localPath 在目标设备解析，只允许普通文件；目录先通过 shell 压缩。节点把文件流直接送到 Gateway，不经过模型文本或 WS 大消息。

Gateway 登记 fileId、来源设备/项目/会话、文件名、大小、SHA256 和存储位置；结果返回 `serverPath`，确保当前 Agent runtime 可以读取。可以复用现有附件目录和流式写入，但不能把“saveSessionFile 返回了 id”等同于已登记、已附到消息或 runtime 已可见。

首版要求 Gateway 与 Agent runtime 共享文件系统；独立进程共用本机磁盘可用。文件结果证明 Gateway 已存储并校验文件，不证明另一台机器的 runtime 已可读取；无共享目录的跨机 runtime 不在首版支持范围，需单独接入挂载或传输，不宣称已有自动检测。

### 下载到客户端

serverPath 相对于当前项目根目录解析，允许当前项目内的已有报告/脚本；fileId 用于本会话已登记上传文件。服务端验证真实路径、符号链接边界与普通文件类型后，生成传输快照或稳定副本，以免传输中源文件变化。

客户端先下载到目标目录内的独占临时文件，校验大小与 SHA256 后再完成落地。默认不覆盖已有文件；overwrite=true 才允许覆盖，并使用平台适配的替换策略，不能先删除旧文件再下载。确认目标已存在时返回 conflict，不能悄悄改名冒充成功。

### 大小、时间与重试

设备传输首版默认单文件上限 1 GiB，可由服务端配置；每设备同时一个传输。现有普通会话上传仍保持原来 50 MiB 上限，仅设备传输显式传独立 maxBytes。持续计数限制实际字节，不能仅相信 Content-Length；首版设全实例设备暂存总配额 5 GiB，预约容量后才接收任务。

文件作业默认总时限 30 分钟、无字节进展 60 秒超时。平台工具不持续挂起等待。首版不承诺断点续传，失败明确返回并清理临时文件，用户/AI 可发起新传输；HTTP Range 与上传分块续传留到后续，不写成 HTTP 自带完整能力。

短期票据只发给节点，不进入 AI 上下文，绑定 jobId/deviceId/项目/会话/方向/固定文件。5 分钟是发起请求的有效期，不是已认证流的寿命；首版过期后重新提交传输，不提供续签或断点续传。节点不能靠自行提交 projectId/sessionId 获取其他会话文件。

设备暂存文件保留 7 天，进行中的传输不清理；被明确保存为项目交付物的文件不随临时文件清理。结果包含保留到期时间。总配额不足明确拒绝，不能偷偷删除尚未到期的用户文件。

## 7. Windows 执行质量

默认优先 pwsh，其次 Windows PowerShell 5.1；首版工具仅接受这两个 Shell，不接受 cmd/bash。cwd 默认客户端用户目录，不能继承服务器项目路径。

命令通过临时脚本/相应 shell 执行策略传递，避免把大脚本全部放入 Windows 命令行。大文件依然使用文件通道。PowerShell 输出编码、原生命令编码和文件本身编码分别处理；提供流式解码，不能对任意字节分块独立“UTF8失败回退GBK”。无法确定文件编码时保留原文件供分析，不承诺所有文本自动识别。

累计 stdout/stderr 超过返回预算只截断返回并标记，不终止正常任务；分页日志有游标。作业日志默认磁盘上限 10 MiB，达到上限继续消费输出但停止扩充日志，明确日志被截断。命令、结果和日志可能含敏感内容，普通运行日志不重复打印完整 payload；设备凭证和传输票据不落操作正文。

## 8. 为什么现在可以开始开发

本方案已明确默认授权方式、设备选择、两个工具的分支、任务寿命、文件来源与落点、大小与配额、覆盖规则、断线结果、首版平台范围。没有必须继续讨论才能开工的产品歧义。

仍需在隔离开发中验证：现有外部入口到 /node-ws 的升级路由、工具调用链实际超时、Windows 进程树清理与中文编码、客户端安装包依赖、Gateway 与当前 runtime 的文件可见性。这些是验收项，不能用“理论可行”当作已测试。

接受本版默认行为后即可按实施清单开发。预估中等偏大，约 3000-4500 行实现代码、另计测试与文档，仅作范围估算。相较旧版增加了作业状态、恢复、文件登记与客户端生命周期处理；不需要改变 ACP 协议，也不替换 Workspace 对话业务。
