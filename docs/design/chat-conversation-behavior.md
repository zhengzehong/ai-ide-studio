# 对话交互与渲染机制设计

## 设计目标

对话页的核心目标是：用户默认看到清晰的最终回复，同时可以按需查看 Agent 的完整执行过程。执行过程包括思考、工具调用、中间说明、权限请求、计划更新等过程事件；最终回复是 Agent 对用户问题的正式答复。

对话 UI 不允许把一轮输出简单压平成“全部工具 + 全部文本”。任何会影响顺序的实现都必须遵守本文规则。

## 核心概念

### 一轮 Turn

一次用户输入触发一次 Agent 生成，称为一轮 Turn。一轮 Turn 由三部分组成：

```text
用户消息
Agent 执行过程
Agent 最终回复
```

用户消息单独显示。Agent 消息显示为一个气泡，气泡内包含：

```text
<执行过程>
  思考块
  工具调用块
  中间回复块
  工具调用块
  权限请求块
  ...
</执行过程>

最终回复
```

### 执行过程

执行过程是 Agent 为了得到最终回复而发生的过程记录。它不是最终答复正文，但用户可以展开查看。

执行过程块包括：

- `thinking`：思考过程。
- `tool`：工具调用和工具状态更新。
- `note`：最终回复之前的中间说明文本。
- `permission`：权限请求和用户确认。
- `elicitation`：Agent 向用户补充提问。
- `plan`：计划模式或任务计划更新。
- `system`：必要的生命周期状态，例如正在启动、正在恢复、正在思考。

执行过程必须按真实事件顺序排列。不能把工具全部挪到顶部，也不能把所有思考合并到最前面。

### 最终回复

最终回复是 Agent 对用户问题的正式回答。页面默认优先展示最终回复。

一轮内如果存在工具调用，最后一次工具调用之后持续输出的普通文本，默认视为最终回复候选。如果后续又出现新的工具调用，则当前最终回复候选降级为执行过程中的 `note`，后续文本重新成为新的最终回复候选。

如果一轮没有工具调用，普通文本可以直接作为最终回复流式显示；生命周期状态和 thinking 仍归入执行过程。

## 数据职责

系统中有三类数据，不允许混用职责。

### `session:update`

`session:update` 是实时 WebSocket 增量事件，用于当前正在生成的一轮。

它负责：

- 让用户立即看到正在生成。
- 实时追加 thinking、回复文本、工具调用、工具状态。
- 维护当前 Turn 的执行过程和最终回复候选。

实时 UI 不能等待数据库查询后才显示。

### `session_events`

`session_events` 是 SQLite 中的过程事件表，是执行过程的持久化来源。

它负责：

- 保存一轮 Turn 内每个过程事件。
- 用 `sequence` 表示真实发生顺序。
- 在刷新、切换会话、服务重启后恢复执行过程。
- 支持历史执行过程按需加载。

只要需要还原执行过程顺序，就必须以 `session_events.sequence` 为准。

### `messages`

`messages` 是 SQLite 中的最终消息表，是历史对话的轻量主入口。

它负责：

- 保存用户消息。
- 保存 Agent 最终回复。
- 支持会话快速加载、摘要、搜索、列表展示。
- 提供执行过程的折叠入口和统计信息。
- 在没有完整事件数据时作为兜底。

`messages` 不负责还原工具调用在正文中的位置。不能仅凭 `messages.tool_calls_json` 决定对话正文顺序。

## 实时生成行为

### 发送后立即反馈

用户发送消息后，前端必须立即：

1. 显示用户消息。
2. 创建当前 Turn 占位气泡。
3. 在执行过程中显示状态，例如“正在准备 Agent...”。

用户不能看到“输入后无反馈”或“转圈消失后整段出现”。

### 实时事件归类

当前 Turn 使用有序块渲染，不再使用 `content + thinking + toolCalls[]` 的压平结构。

收到实时事件时按以下规则处理：

| 事件 | 行为 |
|------|------|
| lifecycle | 写入或更新执行过程状态块 |
| thinking.chunk | 如果最后一块是 thinking，则追加；否则新增 thinking 块 |
| tool.call | 新增 tool 块 |
| tool.update | 按 tool id 更新已有 tool 块；找不到时新增 tool 块兜底 |
| message.chunk | 写入最终回复候选，或在出现后续工具时转为执行过程 note |
| permission.request | 新增 permission 块，并阻塞继续发送 |
| elicitation.request | 新增 elicitation 块，并等待用户回答 |
| plan.update | 更新执行过程中的 plan 块或顶部计划状态 |
| message.done | 标记当前 Turn 完成，固化最终回复和执行过程摘要 |

### 最终回复候选规则

实时阶段允许最终回复候选移动：

```text
reply A
工具 1
reply B
工具 2
reply C
```

展示为：

```text
<执行过程>
  reply A
  工具 1
  reply B
  工具 2
</执行过程>

最终回复
  reply C
```

如果 `reply C` 后又来了 `工具 3`，则变为：

```text
<执行过程>
  reply A
  工具 1
  reply B
  工具 2
  reply C
  工具 3
</执行过程>

最终回复
  后续文本重新生成
```

### 当前 Turn 展示

当前正在生成的 Turn：

- 执行过程默认展开。
- 工具调用实时显示，状态实时更新。
- 思考过程实时显示，但可折叠。
- 最终回复独立显示并流式追加。
- 自动滚动跟随最新输出。

## 历史展示行为

历史消息默认轻量加载。进入会话时先加载 `messages`，快速展示用户消息和 Agent 最终回复。

历史 Agent 气泡显示：

```text
<执行过程 · N 项>  默认折叠

最终回复正文
```

历史执行过程默认不展开，不一次性加载大段工具输入输出或终端日志。

用户点击执行过程时：

1. 按当前 Turn 的 `messageId` 加载对应 `session_events`。
2. 按 `sequence` 还原执行过程块。
3. 工具详情仍可继续懒加载 raw input、raw output、terminal output。

如果某条历史消息没有对应事件，则只显示最终回复；如果有工具摘要，则显示“工具调用 · N 个”的兜底折叠入口。

## 切换会话行为

切换到另一个会话时：

1. 保存当前会话的轻量 UI 状态。
2. 取消订阅旧会话实时事件。
3. 清空当前页面的消息、执行过程和流式状态。
4. 订阅新会话。
5. 加载新会话的 `messages`。
6. 按需加载新会话的事件状态，例如 capabilities、pending permission、未完成 Turn。

切换回来时：

- 已完成 Turn 使用 `messages` 快速恢复最终回复。
- 执行过程保持折叠，点击后从 `session_events` 恢复。
- 如果 Turn 仍在生成，使用已存事件恢复已发生过程，再用新的 `session:update` 继续追加。
- 旧会话的流式内容不能串到新会话。

## 刷新或服务重启行为

刷新页面或服务重启后，前端内存中的实时状态不存在，只能依赖 SQLite。

恢复规则：

- `messages` 用于恢复用户消息和 Agent 最终回复。
- `session_events` 用于恢复执行过程。
- 已完成 Turn 默认不加载完整执行过程，点击后再加载。
- 如果存在事件但没有最终 Agent message，说明可能生成中断；页面显示执行过程和“生成已中断，可重新发送”的状态。

服务重启不能凭空合成最终回复。没有最终消息时，只能展示已持久化的过程和中断提示。

## 去重规则

同一轮 Turn 不允许重复显示。

去重规则：

1. 用户消息使用前端生成的 `clientMessageId`，后端持久化沿用该 id。
2. Agent 当前 Turn 使用同一个 `messageId` 关联实时事件、最终 message、历史执行过程。
3. 如果 `session_events` 已覆盖某个 Turn 的执行过程，`messages` 只展示最终回复，不再把 `tool_calls_json` 作为正文顺序渲染。
4. 如果本地 optimistic message 和服务端 message 内容一致、session 一致、时间接近，应合并为服务端 message。
5. 切换会话时必须按 `session_id` 过滤所有 messages、events、streaming state。

## 默认展开规则

| 场景 | 执行过程 | 思考 | 工具详情 |
|------|----------|------|----------|
| 当前正在生成 | 展开 | 可展开，默认显示摘要或展开当前思考 | 工具行可见，详情按需 |
| 刚完成的最后一轮 | 可短暂保持展开 | 默认折叠 | 工具行可见，详情按需 |
| 历史消息 | 折叠 | 折叠 | 摘要可见，raw 详情按需 |
| 刷新恢复 | 折叠 | 折叠 | 按需加载 |

## 不允许的实现

以下实现会破坏设计，禁止使用：

- 把一轮输出压平成 `thinking + toolCalls[] + content` 后直接渲染。
- 只要 `messages` 存在就忽略 `session_events`。
- 把所有工具调用统一放到最终回复上方或下方。
- 让 `session:event` 和 `session:update` 同时驱动同一实时块，造成重复渲染。
- 切换会话时复用上一个会话的 streaming state。
- 历史消息一次性加载所有工具 raw 数据。

## 验收行为

符合设计的对话页应满足：

- 用户发送后立即出现用户消息和 Agent 占位状态。
- 最新 Turn 的执行过程按事件顺序实时显示。
- 最新 Turn 的最终回复单独显示，并随普通文本流式追加。
- 工具调用不会挤到最终回复顶部。
- 如果最终回复候选后又出现工具调用，候选文本会进入执行过程，新的文本成为最终回复。
- 历史消息默认快速显示最终回复，执行过程折叠。
- 点击历史执行过程后，按事件顺序加载并展示过程块。
- 切换会话、刷新页面、服务重启后不串消息、不重复消息。
