# 对话功能行为定版规范

## 文档目标

本文定义 AI IDE Studio 对话页的目标行为和回归基线。后续重构消息存储、事件表、前端缓存或 WebSocket 协议时，不能破坏本文描述的交互效果。

本文描述的是产品行为目标，不等同于当前代码已经完全满足的实现现状。

## 核心原则

1. 用户默认看最终回复，执行过程按需查看。
2. 最新一轮生成必须实时流式显示，不能等完成后整段出现。
3. 执行过程必须保持真实发生顺序，不能把工具、思考、文本压平后重新排序。
4. 历史消息必须轻量快速展示，工具 raw 数据和长终端输出必须懒加载。
5. 切换会话、刷新页面、服务重启后不能串消息、不能重复消息、不能丢最终回复。

## 核心概念

### Session

一个 Session 是用户与一个 Agent 的连续对话。Session 属于某个 Agent，可关联项目和任务。

Session 负责：

- 保存会话元信息。
- 承载多轮用户消息和 Agent 回复。
- 维护当前是否正在生成、是否有未读更新、是否已关闭等状态。

### Turn

一次用户输入触发一次 Agent 生成，称为一轮 Turn。

一轮 Turn 的展示结构固定为：

```text
用户消息
Agent 气泡
  <执行过程>
    思考块
    工具调用块
    中间说明块
    权限请求块
    计划更新块
    ...
  </执行过程>

  最终回复
```

用户消息和 Agent 回复必须一一按时间顺序显示。Agent 回复不能被拆散到多个无关联位置。

### 执行过程

执行过程是 Agent 生成最终回复之前发生的过程记录。它不是最终答复正文，但用户可以展开查看。

执行过程块包括：

- `stage`：生命周期状态，例如正在准备、正在连接、正在思考。
- `thinking`：模型思考内容或思考摘要。
- `tool`：工具调用、工具状态、工具进度。
- `note`：最终回复之前的中间说明文本。
- `permission`：权限请求。
- `elicitation`：AI 向用户补充提问。
- `plan`：计划模式或任务计划更新。
- `file_change`：文件修改摘要。

执行过程必须按真实顺序排列。

### 最终回复

最终回复是 Agent 对用户问题的正式回答。页面默认优先展示最终回复。

实时生成时，普通文本先作为最终回复候选显示。如果之后又出现工具调用或新的过程事件，之前的候选文本要降级为执行过程里的 `note`，新文本重新成为最终回复候选。

示例：

```text
reply A
工具 1
reply B
工具 2
reply C
```

展示为：

```text
<执行过程>
  中间说明 reply A
  工具 1
  中间说明 reply B
  工具 2
</执行过程>

最终回复 reply C
```

## 发送消息行为

用户点击发送后，前端必须立即：

1. 在对话区追加用户消息。
2. 创建 Agent 占位气泡。
3. 显示“正在准备 Agent...”或同类状态。
4. 禁止出现“发送后空白无反馈”的状态。

如果带图片附件：

- 用户消息中显示附件缩略信息。
- 后端按 runtime 能力决定是否传给 ACP。
- 如果 runtime 不支持图片，应在 UI 或错误状态中明确提示。

## 实时流式行为

### 实时输入源

当前正在生成的 Turn 由 WebSocket 实时事件驱动。实时 UI 不能等待数据库查询后才显示。

实时事件包括：

- lifecycle / stage
- thinking chunk
- message chunk
- tool call
- tool update
- permission request
- elicitation request
- plan update
- usage update
- done

### 当前 Turn 展示

当前正在生成的 Turn：

- 执行过程默认展开。
- 当前工具调用行实时可见。
- 工具状态实时更新，例如执行中、完成、失败。
- 思考和中间说明按出现顺序进入执行过程。
- 最终回复独立显示并流式追加。
- 底部状态显示生成中、耗时等轻量状态。
- 如果用户停留在底部附近，页面自动滚动跟随最新输出。
- 如果用户主动向上滚动，不能强制打断用户阅读。

### 实时去重

同一个实时 delta 只能驱动一次 UI。

如果系统同时存在用于实时显示的事件和用于持久化同步的事件，前端必须明确职责，避免同一 `message.chunk` 或 `tool.update` 同时被两个通道重复 reduce。

## 完成行为

Turn 完成后：

1. 当前 streaming 气泡固化为一条 Agent 历史消息。
2. 最终回复保留在气泡主区域。
3. 执行过程默认折叠。
4. 工具状态统一收敛到完成、失败或取消。
5. 显示耗时、用量、费用等统计信息；如果某些统计不可用，不显示错误占位。
6. 左侧会话运行中状态变为空闲或未读状态。

如果生成失败：

- Agent 气泡显示明确错误。
- 已经产生的执行过程仍可查看。
- 用户可以继续发送新消息或重试。

如果生成被取消：

- 当前 Turn 标记为已取消或已中断。
- 已有过程不应丢失。
- 不应一直显示生成中。

## 历史消息加载行为

进入会话时，历史主内容以轻量消息为准。

目标行为：

1. 先展示用户消息和 Agent 最终回复。
2. 不默认加载所有执行过程。
3. 不默认加载工具 raw input、raw output、完整终端日志。
4. 长会话支持分页或增量加载更早消息。
5. 切换回来时优先使用本地缓存立即展示，再后台刷新。

### 历史消息数量

历史消息不能只固定加载最近 N 条而没有向上加载入口。

如果后端默认限制返回最近 100 条，前端必须提供“加载更早消息”或滚动到顶部自动加载的入口。

### 历史执行过程懒加载

历史 Agent 气泡默认显示：

```text
<执行过程 · N 项>  折叠

最终回复正文
```

用户点击“执行过程”后才加载过程详情。

加载后：

- 按真实顺序显示过程块。
- 工具行可见。
- 文件修改摘要可见。
- raw 工具输入输出继续二级懒加载。

如果没有可恢复的执行过程：

- 不显示空的执行过程入口，或显示“暂无可恢复的执行过程”。
- 不能因为只有 lifecycle 状态就展示误导性的执行过程。

### 工具详情懒加载

工具展示分三级：

1. 气泡级：显示“执行过程 · N 项”或工具数量摘要。
2. 工具列表级：展开执行过程后显示工具名称、状态、简短 preview。
3. 工具详情级：点击单个工具后才加载 raw input / raw output / terminal output。

长终端输出不能默认渲染在历史消息中。

## 切换会话行为

切换到另一个会话时：

1. 当前会话的消息、执行状态、滚动位置和未完成 streaming 状态应保存到会话级缓存。
2. 取消旧会话的内容流订阅。
3. 订阅新会话的内容流。
4. 立即展示新会话缓存；没有缓存时显示加载状态。
5. 后台根据会话版本或 `last_message_at` 判断是否需要刷新。
6. 不能把旧会话的 streaming 气泡显示到新会话。
7. 不能把旧会话的工具调用或执行过程串到新会话。

切换回来时：

- 已完成 Turn 使用历史 message 快速恢复最终回复。
- 执行过程保持折叠，点击后懒加载。
- 如果 Turn 仍在生成，恢复完整当前 Turn 后继续接实时流。
- 不能只取最新一段 event 导致当前 Turn 从中间开始。

## 刷新和重启行为

刷新页面或服务重启后，前端内存状态丢失，恢复规则如下：

1. 已完成 Turn：用历史 message 展示最终回复。
2. 已完成 Turn 的执行过程：默认折叠，点击后加载。
3. 未完成 Turn：显示已恢复的过程和“生成已中断”或“正在恢复”的明确状态。
4. 没有最终回复时，不能伪造最终回复。
5. 存在 raw 事件但没有完成消息时，应显示中断状态，而不是一直生成中。

## WebSocket 行为

每个浏览器 tab 使用一个 WebSocket 连接。

会话内容流按 session 订阅：

- 当前打开的 session 接收完整流式内容。
- 未打开的 session 至少接收全局运行状态、未读状态和列表状态。
- 后台会话完成后，左侧列表必须能显示未读或完成状态。

全局状态广播包括：

- session running / idle
- session title / stage / last message time
- agent status

内容流广播包括：

- update chunk
- tool update
- permission / elicitation
- done

重构后仍必须保证：当前会话实时、后台会话状态可见、切换回来可恢复。

## 模型和模式切换行为

对话页应支持 runtime 暴露的能力：

- 模型列表。
- 当前模型。
- 模式列表。
- 当前模式。
- runtime 配置项。
- 图片支持能力。
- 命令能力。

切换模型或模式时：

- UI 立即反映选择或显示明确失败。
- 不影响已存在的历史消息。
- 不打断正在生成的 Turn，除非 runtime 明确不支持。

## 权限请求和 AI 提问

如果 Agent 请求权限或向用户提问：

- 对话底部显示阻塞交互面板。
- 当前 Turn 显示正在等待用户处理。
- 用户处理后继续当前 Turn。
- 权限结果和提问结果进入执行过程或状态记录。
- 切换会话回来时仍能看到未处理请求。

## 自动滚动行为

自动滚动规则：

- 用户在底部附近时，新内容到达自动滚动到底部。
- 用户已经向上阅读时，新内容不能强行滚到底部。
- streaming、工具输出、执行过程展开、最终回复固化都会触发滚动位置检查。
- 输入框区域不能遮挡最新输出。

## 空状态和加载状态

必须有明确状态：

- 未选择会话：提示选择或新建会话。
- 会话无消息：提示开始对话。
- 发送后等待连接：显示正在准备或正在连接。
- 恢复执行过程：显示正在加载执行过程。
- 执行过程为空：显示暂无可恢复的执行过程，或隐藏入口。
- 失败：显示错误文本。

不能出现长时间空白、转圈消失、无响应的状态。

## 不允许破坏的行为

后续重构禁止出现以下问题：

- 用户消息发送后没有立即显示。
- 流式输出消失，变成完成后整段出现。
- 工具调用全部挤到最终回复前面或后面。
- 执行过程和最终回复顺序错乱。
- 历史消息默认展开所有工具详情。
- 历史消息一次性加载大量 raw events。
- 切换会话后显示上一会话的消息或 streaming 状态。
- 切换回来当前执行中消息从中间开始。
- 刷新后已完成消息缺失。
- 左侧运行中、未读、空闲状态不更新。
- 输入框遮挡最新输出。

## 回归验收清单

后续重构完成后至少验证：

1. 简单问答：用户发送后立即流式显示，完成后执行过程折叠。
2. 工具调用任务：执行过程按“文本/工具/文本/工具/最终回复”的真实顺序显示。
3. 长工具输出：历史打开不加载 raw 输出，点开工具详情才加载。
4. 长会话：可以加载更早消息，不只显示最近固定数量。
5. 切换会话：消息不串，缓存立即展示，后台刷新不闪烁。
6. 后台运行：切走后左侧状态更新，切回来能恢复完整当前 Turn。
7. 刷新页面：已完成回复存在，执行过程按需加载。
8. 失败/取消：状态明确，不无限生成中。
9. 图片消息：支持 runtime 正常显示，不支持 runtime 明确提示。
10. 模型/模式切换：UI 状态正确，失败有提示。
