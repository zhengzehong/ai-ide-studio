# 定时任务系统 — 功能设计文档

> 版本：v1.0 | 日期：2026-06-02 | 状态：设计中

---

## 一、功能概述

定时任务是 AI IDE Studio 的自动化核心能力之一。用户或 Agent 创建一条「定时规则」，系统按照设定的时间周期自动执行指定动作，实现**无人值守的 AI 工作流**。

### 核心能力

| 能力 | 说明 |
|------|------|
| **定时触发** | 基于 cron 表达式，按分钟/小时/天/周/月等周期自动触发 |
| **多种动作** | 触发后可以「创建任务」或「直接给 Agent 发 Prompt」 |
| **Agent 自主管理** | Agent 通过工具自行创建、查询、修改、启停定时规则 |
| **项目隔离** | 规则归属项目，触发产物（任务/会话）也归属同一项目 |
| **执行追溯** | 每次触发有记录，可追溯到产生的任务或会话 |

### 业务场景举例

1. **每日代码审查** — 每天早上 9 点自动创建"审查昨日提交"任务，分派给架构师 Agent
2. **定时数据报告** — 每周一早 10 点，直接给分析 Agent 发 prompt "生成上周数据周报"
3. **Agent 自建闹钟** — 用户对话中说"每天下午 3 点提醒我 review PR"，Agent 调用工具自动创建定时规则
4. **批量定时巡检** — 运维 Agent 每小时自动检查服务状态

## 二、完整业务闭环

### 2.1 闭环一：用户在 UI 创建定时规则 → 系统自动执行

```
用户打开「自动化规则」页面
  → 点击「新建规则」
  → 填写：规则名称、cron 表达式、选择动作类型
     ├─ 动作 = 创建任务：填写任务标题、描述、指派 Agent（可选）
     └─ 动作 = 发送 Prompt：选择目标 Agent、填写 prompt 内容
  → 创建成功，规则出现在列表中，显示下次执行时间

到达 cron 时间点
  → 系统自动执行动作
     ├─ 创建任务 → 任务出现在「任务看板」→ 若指派了 Agent 则自动开始对话
     └─ 发送 Prompt → 新建或复用会话 → Agent 开始工作
  → 执行记录写入，UI 实时更新「上次运行」「成功/失败次数」

用户在规则列表中
  → 可查看执行历史（每次触发的时间、成功/失败、关联的任务）
  → 可编辑规则（改 cron、改动作配置）
  → 可启停规则
  → 可删除规则
```

### 2.2 闭环二：Agent 通过工具管理定时规则

```
用户在对话中说："帮我设置一个每天早上9点的代码审查提醒"

Agent 理解意图后
  → 调用 core.schedule.create 工具
     参数：name="每日代码审查", cron="0 9 * * *", action="create_task",
           taskTitle="审查昨日代码提交", assignAgentId=当前Agent
  → 系统创建规则，返回规则信息给 Agent
  → Agent 回复用户："已创建定时规则，每天 09:00 会自动创建代码审查任务"
  → 用户在「自动化规则」页面可以看到这条规则

后续 Agent 也可以
  → 调用 core.schedule.list 查看当前项目的所有规则
  → 调用 core.schedule.update 修改 cron 或内容
  → 调用 core.schedule.toggle 暂停/恢复规则
  → 调用 core.schedule.delete 删除规则
  → 调用 core.schedule.executions 查看某条规则的执行历史
```

### 2.3 闭环三：定时触发 → 任务 → Agent 执行 → 完成

```
系统 cron 引擎检测到规则匹配当前时间
  → 创建任务（source=schedule），任务归属规则所在项目
  → 任务自动指派给配置的 Agent
  → 系统为该 Agent 创建会话，发送 prompt
  → Agent 开始执行，流式输出到对话
  → Agent 完成，任务状态变为「审查中」
  → 用户在任务看板确认，标记「已完成」

如果执行失败
  → 任务状态变为「已阻塞」
  → 执行记录标记 failed + 错误原因
  → 不影响下次触发
```

## 三、功能清单

### 3.1 规则管理

| 功能 | 操作者 | 说明 |
|------|--------|------|
| 创建规则 | 用户 / Agent | 设置名称、cron、动作类型和配置、所属项目 |
| 编辑规则 | 用户 / Agent | 修改 cron、动作配置、名称等 |
| 启停规则 | 用户 / Agent | 暂停后不再触发，恢复后继续 |
| 删除规则 | 用户 / Agent | 删除后不再触发，执行历史保留 |
| 查看规则列表 | 用户 / Agent | 按项目过滤，显示状态、下次运行、统计 |
| 手动立即执行 | 用户 | 不等 cron 时间，立即触发一次 |

### 3.2 动作类型

| 动作 | 触发行为 | 产物 |
|------|---------|------|
| **创建任务** | 在任务看板创建一条任务，可选指派 Agent 自动执行 | 任务（+ 会话，如果指派了 Agent） |
| **发送 Prompt** | 直接给指定 Agent 发一条消息，新建或复用会话 | 会话 |

### 3.3 执行追溯

| 功能 | 说明 |
|------|------|
| 执行历史列表 | 每条规则可查看所有触发记录：时间、成功/失败、关联任务 |
| 任务溯源 | 由定时规则创建的任务，可追溯到来源规则 |
| 失败记录 | 记录失败原因，失败不阻塞后续触发 |

### 3.4 执行控制

| 功能 | 说明 |
|------|------|
| 最大执行次数 | 可选设置，达到后自动禁用规则（如"只执行 10 次"） |
| 分钟级去重 | 同一规则同一分钟只触发一次 |

### 3.5 Agent 工具

Agent 可通过以下 6 个工具完整管理定时规则：

| 工具名 | 功能 |
|--------|------|
| `core.schedule.create` | 创建规则 |
| `core.schedule.list` | 查看规则列表 |
| `core.schedule.update` | 修改规则 |
| `core.schedule.delete` | 删除规则 |
| `core.schedule.toggle` | 启停规则 |
| `core.schedule.executions` | 查看执行历史 |

**默认绑定**：`core.schedule.*` 系列工具属于 `builtin` 类型，`defaultScope: 'global'`，即**所有 Agent 默认可用**，无需手动绑定。如果某个 Agent 不需要定时任务能力，可在 Agent 配置中移除该工具绑定。

### 3.6 权限控制

Agent 操作定时规则时存在权限边界：

| 操作 | 权限范围 | 说明 |
|------|---------|------|
| 创建规则 | 当前项目 | Agent 只能在自己所属会话的项目下创建规则 |
| 查看规则列表 | 当前项目 | Agent 默认只能看到当前项目的规则 |
| 修改规则 | 自己创建的 | Agent 只能修改 `created_by` 为自己的规则 |
| 删除规则 | 自己创建的 | Agent 只能删除自己创建的规则 |
| 启停规则 | 自己创建的 | Agent 只能启停自己创建的规则 |
| 查看执行历史 | 当前项目 | 当前项目内任意规则的执行历史都可查看 |

**权限层级**：

```
用户（UI 操作）
  → 项目管理员权限：可管理当前项目下所有规则（不区分创建者）

Agent（工具调用）
  → 默认权限：只能管理自己创建的规则（created_by = agent:{自己的ID}）
  → 可查看当前项目下所有规则列表和执行历史（只读）
```

**越权处理**：Agent 尝试修改/删除/启停非自己创建的规则时，工具返回权限错误，不执行操作。

## 四、规则数据结构

### 4.1 一条规则包含的信息

| 字段 | 说明 | 示例 |
|------|------|------|
| 规则 ID | 唯一标识 | `rule-a1b2c3d4` |
| 名称 | 规则的显示名称 | "每日代码审查" |
| 描述 | 可选，补充说明 | "自动创建代码审查任务" |
| 所属项目 | **必填**，规则归属哪个项目 | `proj-xxx` |
| Cron 表达式 | 5 字段标准格式：分 时 日 月 周 | `0 9 * * 1-5` |
| 动作类型 | `create_task` 或 `send_prompt` | `create_task` |
| 动作配置 | 根据动作类型不同，结构不同（见下方） | — |
| 是否启用 | 开/关 | `true` |
| 最大执行次数 | 可选，达到后自动禁用 | `null`（无限） / `10` |
| 创建者 | 谁创建的：用户还是某个 Agent | `human` / `agent:claude-dev` |
| 统计信息 | 成功次数、失败次数、上次运行、上次失败、下次运行 | — |

### 4.2 动作配置

#### 动作 = 创建任务

| 字段 | 必填 | 说明 |
|------|------|------|
| 任务标题 | ✅ | 创建的任务的标题 |
| 任务描述 | | 任务详情 |
| 指派 Agent | | 选一个 Agent，触发后自动让它执行 |
| Prompt 模板 | | 自定义发给 Agent 的指令，不填则用默认模板 |

> 默认 Prompt 模板：`你被分派了一个任务：{title}\n\n任务描述：{description}\n\n请开始工作。`
>
> 支持变量：`{title}`、`{description}`、`{date}`（当天日期）、`{time}`（当前时间）

#### 动作 = 发送 Prompt

| 字段 | 必填 | 说明 |
|------|------|------|
| 目标 Agent | ✅ | 给哪个 Agent 发 |
| Prompt 内容 | ✅ | 发送的消息内容，支持 `{date}`、`{time}` 变量 |
| 复用会话 | | 指定一个已有会话 ID，为空则每次新建 |

### 4.3 执行记录

每次规则触发产生一条记录：

| 字段 | 说明 |
|------|------|
| 触发时间 | 什么时候触发的 |
| 状态 | 成功 / 失败 |
| 关联任务 ID | 动作=创建任务 时，创建出的任务 ID |
| 关联会话 ID | 动作=发送Prompt 时，使用的会话 ID |
| 错误信息 | 失败时的原因 |

## 五、UI 交互说明

### 5.1 规则列表页（自动化规则）

**入口**：左侧导航栏「自动化规则」

**页面结构**：
- 顶部：标题 + 「新建规则」按钮
- 列表：表格形式展示所有规则（按当前项目过滤）

**列表每行显示**：

| 列 | 内容 |
|----|------|
| 启用开关 | 点击切换启停 |
| 规则名称 | 名称 + 动作类型标签（"创建任务"/"发送Prompt"） |
| Cron | cron 表达式 + 中文描述（如"每天 09:00"） |
| 执行统计 | `成功 12 / 失败 0` |
| 上次运行 | 相对时间："3 小时前" |
| 下次运行 | 绝对或相对时间 |
| 操作 | 编辑 / 立即执行 / 删除 |

**行展开**：点击行展开显示最近执行历史（最近 10 条）

### 5.2 新建/编辑弹窗

**字段**：

1. **规则名称**（必填，文本框）
2. **Cron 表达式**（必填，文本框 + 快捷模板按钮 + 实时中文描述）
   - 快捷模板：每分钟 / 每 30 分钟 / 每小时 / 每天 9:00 / 每周一 9:00 / 每月 1 号
   - 输入合法 cron 时，下方实时显示：中文描述 + 下次执行时间
3. **动作类型**（下拉选择）
   - 选「创建任务」→ 显示：任务标题（必填）、任务描述、指派 Agent、Prompt 模板
   - 选「发送 Prompt」→ 显示：目标 Agent（必填）、Prompt 内容（必填）
4. **最大执行次数**（可选，数字输入，placeholder "不限"）
5. **描述**（可选，文本框）

**编辑模式**：预填所有已有值，弹窗标题改为「编辑定时规则」

### 5.3 执行历史

**触发方式**：规则行展开 或 点击某规则进入详情

**历史列表每行**：

| 列 | 内容 |
|----|------|
| 时间 | "2026-06-02 09:00" 或 "3 分钟前" |
| 状态 | 🟢 成功 / 🔴 失败 |
| 产物 | 成功时：显示任务标题（可点击跳转任务看板） |
| 错误 | 失败时：错误信息 |

默认显示 20 条，可加载更多。

## 七、业务规则

| 编号 | 规则 |
|------|------|
| BR-01 | 规则**必须归属一个项目**，不存在全局规则 |
| BR-02 | 同一规则在同一分钟内只触发一次，30 秒轮询保证不遗漏 |
| BR-03 | 触发失败不阻塞下次触发，失败有独立计数和记录 |
| BR-04 | 设了最大执行次数的规则，达到后自动禁用，不再触发 |
| BR-05 | Agent 创建的规则归属 Agent 当前会话所在的项目 |
| BR-06 | 规则删除后，已产生的任务和会话不受影响 |
| BR-07 | 规则引擎在后端启动时自动运行，不需要用户手动开启 |
| BR-08 | 由定时规则产生的任务，`source` 标记为 `schedule`，可追溯到规则 |
| BR-09 | 「发送 Prompt」动作中，若指定复用会话但会话不存在，则新建会话 |
| BR-10 | cron 表达式在创建和编辑时校验，非法格式直接拒绝 |
| BR-11 | Agent 只能修改/删除/启停自己创建的规则（`created_by` 匹配），越权返回错误 |
| BR-12 | Agent 可查看当前项目所有规则列表和执行历史（只读不受 `created_by` 限制） |
| BR-13 | 用户在 UI 操作不受 `created_by` 限制，可管理当前项目下所有规则 |
| BR-14 | `core.schedule.*` 系列工具为 `builtin` 全局工具，所有 Agent 默认绑定，无需手动配置 |
