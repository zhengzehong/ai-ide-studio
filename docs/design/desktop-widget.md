# 桌面悬浮部件（Desktop Widget）设计文档

桌面悬浮部件是 Electron 模式下的常驻迷你窗口，用于在不切回主窗口的情况下查看正在执行、等待确认或有新回复的会话。

## 设计原则

- **会话不丢失**：同一 Agent 同时存在多个关注会话时，每个会话都必须可见，不能只保留一个代表会话。
- **项目归属明确**：活动按 Agent 与项目组合分组，项目名始终显示；未绑定项目时显示“未归属项目”。
- **单行高密度**：每个会话固定占一行，顺序为状态、会话标题、直接关联任务和活动时间。
- **真实状态**：执行中来自 Session active prompt，未读来自统一的 Session 已读时间，待确认来自该 Session 直接关联的 Task。
- **精确操作**：点击会话打开精确的 Project/Session，导航成功后只标记该会话已读。

## 信息结构

```text
coder-codex · AI IDE Studio                 2 个会话
  执行中  构建最新 PRD - 排查首次文件预览未展示   刚刚
  未读    桌面浮窗优化 - 多会话活动展示方案       6 分钟

openclaw-codex · GowClaw                    1 个会话
  待确认  多卡推理排查 - 分析异常 910B2/910B3   22 分钟
```

组头只承担 Agent、项目和会话数量表达。会话行不换行；内容超出时分别截断会话标题和任务标题，完整内容通过悬停提示查看。

## 关注集合

满足以下任一条件的 Session 进入 Widget：

- 当前存在 active prompt。
- 最后消息时间晚于最后已读时间。
- 直接关联的 Task 状态为 `needs_input` 或 `blocked`。

已完成且已读的普通 Session 不进入 Widget。删除或归档的 Session 始终排除。

状态按待确认/阻塞、执行中、未读的顺序决定单行左侧主标签。运行、未读和待确认仍作为独立事实保留，因此筛选和统计不会因主标签选择而丢失信息。

## 分组与排序

- 分组键为 `agentId + projectId`；同一 Agent 在两个项目工作时显示两个组。
- 组内先按待确认/阻塞、执行中、未读排序，再按最近活动时间倒序。
- 分组顺序由组内最高优先级会话决定。
- 返回结果限制的是 Session 数量，不是 Agent 数量，防止一个 Agent 的兄弟会话被静默折叠。

## 筛选与统计

状态筛选在“全部、运行中、待处理、未读”之间循环。“全部”表示全部关注会话，不表示全部历史会话。

底部同时显示不同 Agent 数、关注会话数、执行中数和未读数。统计基于 Session 独立事实，不使用 Agent Runtime 在线状态冒充会话执行状态。

## 更新机制

Widget 监听 Agent 状态、Session 活跃/完成/变更和 Task 更新事件，事件到达后重新拉取轻量活动摘要。Widget 不订阅完整聊天内容流，完整对话仍由 Workspace 负责。

## Electron 行为

- Widget 是不可调整大小的半透明常驻窗口。
- 支持项目筛选、主题切换、置顶、隐藏和打开主窗口。
- 打开会话时携带项目与 Session 定位信息，主窗口完成内部导航后才更新已读状态。
- Widget 关闭或隐藏不影响后台 Agent、Session 或 Task 的运行。
