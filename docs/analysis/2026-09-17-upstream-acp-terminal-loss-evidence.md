## 5. 值得上游排查的点

1. **终帧丢失**(主诉):回合在 CLI 侧已 `end_turn`,但 ACP 侧没有 terminal/result 帧送达客户端;
   请检查适配器在长回合 / 工具密集 / 长静默后的 result 转发路径。
2. **两段长静默**(19:27→19:47 约 20 分钟;19:49→21:57 约 2 小时 08 分):
   期间无任何帧(含心跳),随后又能继续产出 —— 是否有流中断重连、模型侧挂起或适配器缓冲?
3. **同栈对照**:2026-09-15 另一项目出现同类"多小时挂起"(3 个会话的 prompt 分别 2.2-2.3 小时才收束,
   平台侧观察到最长 idle 6.7 小时);当时无自主回合机制参与,提示问题可能不止一种触发路径。
4. **期望的适配器侧保底**:当 result/terminal 帧缺失时,基于 turn 完成信号(CLI transcript `end_turn`)
   补发终帧或给出可观测的超时诊断事件;流挂起时输出诊断帧,避免客户端无限等待。
