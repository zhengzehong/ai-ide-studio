# ACP 会话生命周期与对话体验架构分析

## 已记录待修问题
- 发送 prompt 后前端只追加用户消息，不立即创建 assistant pending/正在思考占位。
- Codex 首包可能需要十几秒到几十秒，用户会误以为卡住。
- 新建会话目前同步等待 ACP session/new，首次 Codex 初始化可达十几秒，体验像卡死。

## 分析目标
1. 梳理当前何时启动 ACP 进程、何时创建 ACP session。
2. 确认同一 Agent 多个 Codex 会话是否复用 ACP 进程。
3. 判断当前模型是否合理。
4. 设计长期合理架构：本地会话、Agent runtime 进程、ACP session、空闲回收、前端状态机。

## 输出
- 当前实现证据。
- 主要问题。
- 推荐架构与分阶段落地计划。
