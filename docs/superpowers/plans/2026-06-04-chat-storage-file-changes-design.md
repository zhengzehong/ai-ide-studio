# 对话存储与文件修改记录设计

## 目标

- 明确新的对话存储模型：`messages + turn_process_items`。
- 明确文件修改统计、过程记录、最终汇总在新模型中的存储方式。
- 保持设计文档是稳定功能设计，不写阶段式实现计划。

## 执行清单

1. 检查现有数据库表、后端 store、RPC、前端渲染中与文件修改/工具调用相关的存储路径。
2. 编写新的对话存储设计文档，说明主消息、执行过程、工具调用、权限、文件修改的边界。
3. 单独分析文件修改统计：一次对话可能出现多少次、当前如何存、新方案如何存。
4. 输出结论与后续实现建议。

## 验收标准

- 文档说明人能看懂，不依赖代码上下文。
- 清楚区分最终回复、执行过程、文件修改事实、文件修改汇总。
- 清楚说明为什么不拆多个过程表，以及未来何时需要拆。
