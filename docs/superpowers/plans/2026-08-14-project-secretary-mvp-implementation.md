# 项目内秘书最小闭环实施计划

## 目标

在不改变现有自主工作、普通会话和定时任务语义的前提下，增加项目内秘书的最小可用闭环：配置秘书、选择执行/观察 Agent、定时/手动/Agent 完成触发、持久化运行队列、邮箱 Thread、独立对话，以及 PC/APP 的基础查看。

## 明确不做

- 不开放跨项目访问。
- 不做 HTML 文件运行预览。
- 不新增秘书动作权限编辑器。
- 不把秘书邮件映射为普通 Session 列表。
- 不修改既有 autonomy 配置、`autonomy_tick` 或普通定时任务行为。

## 实施步骤

- [x] 新增数据库迁移、秘书/触发/运行/Thread/Entry store 与共享类型。
- [x] 新增秘书生命周期、固定 runtime/chat Session、运行队列和报告工具。
- [x] 接入 cron、手动运行、`session:committed_done` 观察事件，并实现项目/Agent 过滤与幂等。
- [x] 新增秘书 RPC、WS 事件和 PC 邮箱/配置/聊天界面。
- [x] 新增 APP 秘书入口、邮箱详情、聊天和附件基础查看。
- [x] 补充单元/集成测试、架构文档、使用说明并执行全量验证。
- [x] 独立审查改动范围与兼容性；仅合并代码到 `prd`，不重启 PRD 服务。

## 验收标准

- 同一项目可创建多个秘书，配置互不覆盖。
- 运行触发先持久化到队列，服务重启或 Session 忙碌不会丢失事件。
- 只处理当前项目和配置的观察 Agent，不触发其他项目。
- 邮箱按 Thread 聚合，支持未读、归档、Markdown 正文和多个常见附件。
- 秘书后台运行与独立对话 Session 隔离，不污染普通会话列表。
- 既有自主工作、规则引擎、普通 Session、PC/APP 其他页面回归测试通过。
