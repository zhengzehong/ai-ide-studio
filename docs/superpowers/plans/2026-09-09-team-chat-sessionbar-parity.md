# 团队会话与普通 Agent 对齐实施计划

## 目标

- 团队中间对话沿用 `ConversationPane`，修复 Agent 完成后回复从列表消失及历史回载覆盖本地完成消息的问题。
- 团队左侧会话列表复用普通 `SessionBar` 的行/头部视觉与状态交互语义，不改变普通 Workspace 的业务行为。
- 不改后端、数据库和 ACP；仅在 `ui/` 与前端回归测试内修改。

## 实施步骤

1. 在团队聊天聚合纯函数测试中补充复现：成员消息统一展示 session、完成消息保留 sender、落库延迟和空历史不覆盖完整消息。
2. 修复 `TeamChatPane`：完成消息统一使用团队展示 session ID；历史合并按非空内容、已完成状态、工具过程优先；清理完成回载竞态。
3. 抽取普通会话列表共享的视觉/行结构，团队列表接入共享组件，保留团队专属 RPC 回调和状态判断。
4. 补充团队列表与普通 `SessionBar` 的结构回归测试，确认普通 Workspace 文件无业务改动。
5. 运行定向 Vitest、`npm test`、UI tsc、lint、build，检查 diff 与 worktree 状态后提交并送审。

## 验收标准

- 团队消息：用户一条消息对应 Master/成员的 Agent 回复；完成后回复、工具过程、文件变更仍可见，不因历史接口暂时返回空而消失。
- 左侧列表：宽度、头部、行间距、选中蓝边、状态点、时间和操作按钮与普通 `SessionBar` 同构；团队运行状态不由 `status=active` 推断。
- Workspace 普通 Agent 页面行为和后端代码不变。
- 定向与全量测试、tsc、lint、build 全部通过。
