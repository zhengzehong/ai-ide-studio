# EXE 远程菜单白屏修复实施计划

## 目标

修复远程 EXE 客户端点击菜单时因懒加载分块失败而出现的空白页面，保留现有 SPA 路由和远程部署方式，不改数据库、业务 API 或 WebSocket 协议。

## 顺序

1. 为静态资源缺失返回 404、路由分块失败提示和一次性刷新补充回归测试。
2. 修改静态资源 SPA fallback，排除 `/assets/` 及带扩展名的资源路径。
3. 将页面 Suspense 限制在内容区域，增加可重试的路由错误边界。
4. 为动态导入增加一次性 reload 保护，避免旧版本 chunk 或短暂网络失败形成永久白屏。
5. 运行定向测试、类型检查、lint、构建和 diff 检查。
6. 请求代码审查，修复审查问题后提交并合并到 `prd`。

## 验收标准

- 不存在的 `/assets/*.js` 不再返回 `index.html`，而是 404。
- 正常切换菜单时侧栏和顶部保持显示，内容区展示加载状态。
- 动态 chunk 加载失败时显示中文错误和“重新加载”操作，不出现空白 `#root`。
- 自动刷新最多执行一次，网络持续失败时不会刷新死循环。
- 不改变现有 API、WS、业务数据和 PRD 运行中的服务。
