# Files Present Design

## Goal

Allow an Agent to present one or more project files as durable conversation deliverables. Users can open a card, switch between files, and read rendered Markdown on PC and mobile.

## Tool Contract

The global builtin tool is named `files.present`:

```json
{
  "title": "本次交付",
  "files": [
    { "path": "docs/report.md", "title": "分析报告" },
    { "path": "docs/plan.md", "title": "实施方案" }
  ]
}
```

`files` contains 1-20 unique project-relative paths. `title` and each file title are optional. The handler requires project and work-directory context, validates every path with the existing filesystem security policy, verifies that every entry is a file, and returns a small manifest containing project ID, relative paths, names, extensions, sizes, kinds, and creation time. File content is never embedded in the tool output or message history.

## Conversation Flow

During a live turn, clients parse the `files.present` tool output from realtime process blocks and render a deliverable card immediately. At turn completion, `message-presentations.ts` extracts the manifest into the existing `messages.presentations_json` column. PC history receives it through the existing HTTP message query; mobile history receives it through `sessions.messages` RPC.

The presentation type becomes a union of `preview` and `files`. Realtime and persisted file presentations are deduplicated by a stable presentation ID generated by the handler.

## PC Interaction

The card shows the presentation title, file count, and a compact file list. Clicking it opens a modal. The modal has a left file list and right content pane. Selecting a file loads its current content through the existing authenticated `fs.read` RPC. Markdown uses `MarkdownRenderer`; other text uses a monospaced viewer. Loading, missing, truncated, and read-error states are explicit.

## Mobile Interaction

The card opens a full-screen overlay. A horizontally scrollable file selector switches files. The body reuses the existing `FileDetail` rendering stack, including Markdown, code, plain text, images, and binary handling. File content is loaded only when selected.

## Agent Behavior

The shared AI IDE system prompt instructs Agents to call `files.present` after producing user-facing reports, plans, specifications, or other deliverable files. The instruction does not require the tool for internal implementation files unless presenting them benefits the user.

## Security And Limits

- Project context and work directory are mandatory.
- Absolute paths, hidden paths, path traversal, directories, missing files, and blocked sensitive files are rejected.
- At most 20 unique files are accepted.
- History stores metadata only; current file content is read on click.
- Existing `fs.read` size truncation remains authoritative.

## Scope

Included: builtin tool, persistence union, realtime/history cards, PC modal, mobile overlay, prompt instruction, tests, and documentation.

Excluded: immutable snapshots, file editing inside the modal, arbitrary files outside the project, and changes to ACP/Writer/Realtime protocols.
