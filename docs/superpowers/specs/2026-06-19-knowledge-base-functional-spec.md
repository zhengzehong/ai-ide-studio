# 知识库(LLM Wiki)功能逻辑文档

> 文档性质:**功能逻辑**(WHAT + 产品逻辑),供代码工程师据此产出**代码实现方案**(后端架构 / 前端实现 / 工具签名等 HOW)。
> 产出人:产品经理 · 日期:2026-06-19
> 配套原型:`prototypes/knowledge-base.html`(交互、视觉、信息层级以原型为准)

---

## 1. 背景与目标

### 1.1 要解决什么问题
AI IDE Studio 目前没有"知识"沉淀层(README 明确标注 Memory/RAG 尚未实现)。每个 Agent 会话各自为战,项目的架构认知、约定、踩坑经验散落在一次次对话里,新会话/新 Agent 进来都要重新理解。我们要建一个**人和 AI 都能读写**的知识库,让认知可以沉淀、复用、跟随代码演进。

### 1.2 为什么是 LLM Wiki 而不是 RAG/向量库
两条硬约束决定了选型:
- **人也要能看能编辑,而且很重要**:知识库以纯 markdown 存储,人可读可改;向量库对人不可读,排除。
- **一切由 Agent 调 MCP 工具驱动**(本项目既有架构):知识 = markdown 页面,AI 通过工具读写,天然契合。

LLM Wiki 形态:纯 markdown 页面 + `[[wikilink]]` 双向链接 + 一个索引页。AI 先读索引,再顺着链接导航(index-first 检索),无需向量召回。

### 1.3 本期目标(一句话)
做一个**多知识库**的 LLM Wiki:每个项目默认一个项目库,可建多个共享库并被多项目挂载;**人和 AI 都能读写**;AI 通过 `core.kb.*` 工具**直接写入**(不走自动归档/审批),所有写入进**可撤销的活动日志**;代码派生的页面能**检测陈旧并由 AI 刷新**。

## 2. 核心概念

### 2.1 知识库(KB)= 一等公民
KB 不是单例"全局库",而是可创建、可命名的对象。两个关键属性:

- **kind(种类)**
  - `project`:绑定到某个项目,随项目而生(每个项目自动创建一个)。
  - `shared`:共享库,不绑定单一项目,可被**多个**项目挂载(多对多)。
  - → "全局知识库"的真正含义 = 可被多项目挂载的 `shared` 库,且**可以有多个**,不是一个。

- **src(来源/维护方式)**
  - `manual`:人 + 会话沉淀。人手写、AI 沉淀经验。
  - `code`:跟随代码库。页面由代码生成,能检测陈旧、可被 AI 刷新。

### 2.2 挂载(Mount)
项目通过"挂载"使用共享库。某个项目"**提供给 AI 的知识**" = 它的项目库 ∪ 它挂载的所有共享库。
- 挂载关系是多对多:一个共享库可被多个项目挂载,一个项目可挂载多个共享库。
- 卸载只解除关系,不删除共享库内容。

### 2.3 页面(Page)与双向链接
- KB 由若干 markdown 页面组成,每个 KB 有一个**索引页**(AI 检索入口)。
- 页面正文用 `[[页面标题]]` 互相链接,可**跨库**跳转。
- 每个新页面至少要有 1 个入链(避免孤儿页);系统能算**反向链接**(谁链到了我)。
- 页面记录作者来源:`human` 或 `ai`;`code` 来源页面额外记录它派生自哪些源文件 + 是否 `stale`(陈旧)。

### 2.4 活动日志(Activity Log)= 安全网
**不做事前审批**。AI 通过工具直接写,人也直接编辑。每一次写入(建页/改页/刷新)都落一条活动记录:谁(human/某 Agent)、用了哪个工具、动了哪个页面、何时、备注。每条都能**一键撤销**(回滚到该次写入前的版本)。安全性来自"事后可回溯可撤销",而非"事前拦审批"。

## 3. 数据实体(逻辑层,字段语义为准;具体表结构/类型由工程师定)

> 注:本项目既有约定是 SQLite + 无外键 + 软引用 `*_id`。下面只说**需要存什么、字段含义**,索引/类型/迁移编号交给工程师。

### 3.1 知识库 KB
- `id`、`name`、`kind`(project/shared)、`src`(manual/code)、`icon/desc`(展示用)
- `project_id`:仅 `kind=project` 时有值(归属项目);`shared` 为空
- 创建/更新时间
- 约束:每个项目有且仅有一个 `kind=project` 的库(创建项目时自动建)。

### 3.2 页面 Page
- `id`、`kb_id`(属于哪个库)、`title`、`section`(分组/目录)、`summary`(索引页用的一句话)
- `body`(markdown 正文,含 `[[wikilink]]`)
- `author`(human/ai)、`by`(具体是谁:用户 or AgentId)、更新时间、`tags`
- `is_index`:是否该库的索引页
- 仅 `src=code` 的页面额外有:`src_files`(派生自哪些文件路径)、`stale`(是否陈旧)、`src_fingerprint`(用于陈旧检测,见 §6)

### 3.3 挂载关系 Mount(多对多)
- `project_id` + `kb_id`(被挂载的 shared 库)+ 挂载时间。
- 仅 `shared` 库可被挂载;`project` 库不进此表(它天然只属于自己项目)。

### 3.4 活动日志 Activity
- `id`、`kb_id`、`page_id`、`act`(create/edit/refresh)、`actor`(human/AgentId)、`tool`(用了哪个 `core.kb.*` 工具,人工编辑记 `manual`)、`at`、`note`
- **回滚所需**:`prev_body`(本次写入前的正文快照),撤销时把页面还原到 `prev_body`;create 类的撤销 = 删除该页。
- 撤销本身也记一条 activity(act=revert),保证链路可追溯。

## 4. AI 工具清单(`core.kb.*`,这是 AI 直接读写知识库的入口)

> 工具是 AI 操作知识库的唯一方式。下面给**职责和输入输出语义**,精确签名/参数类型由工程师定。
> 设计原则对齐既有架构:**读多写少都靠工具,无自动级联**;写工具必落 activity 日志。

**读取类**
1. `core.kb.list` — 列出某项目可见的知识库(它的项目库 + 已挂载的共享库)。AI 检索的第一步:先知道有哪些库。
2. `core.kb.read_index` — 读某个库的索引页。**这是 index-first 检索的入口**,AI 拿到目录后决定读哪页。
3. `core.kb.read_page` — 按页面标题/ID 读正文。返回正文 + 反向链接 + 出链。
4. `core.kb.search` — 在可见知识库内按关键词找页面(标题/正文文本匹配即可,不要求向量)。

**写入类(每次写入必落 activity 日志,可撤销)**
5. `core.kb.create_page` — 新建页面。入参:kb_id、title、section、body、tags。**强约束**:必须指定/已存在至少一个入链来源,否则提示会成孤儿页(可创建但要警示)。
6. `core.kb.update_page` — 改写已有页面正文。写入前自动把旧正文存入 activity 的 `prev_body`。
7. `core.kb.refresh_from_code` — 仅对 `src=code` 库:让 AI 依据当前源文件重写某页,并清掉 `stale` 标记、更新 `src_fingerprint`。这是"wiki 跟随代码"的写动作。

**管理类**
8. `core.kb.create_kb` — 新建知识库(指定 kind、src、name)。常由人在前端触发,也允许 AI 在合理场景调用。
9. `core.kb.mount` / `core.kb.unmount` — 把共享库挂到当前项目 / 取消挂载。
10. `core.kb.revert` — 按 activity 记录撤销某次写入(还原 `prev_body`,create 则删页)。

> 工具暴露:沿用本项目既有的工具注册/暴露机制(参考 `studio.*` / `core.*` 现有工具如何注册给 Agent),把 `core.kb.*` 注册进同一套体系。

## 5. 关键用户路径(人的视角)

入口:左侧图标栏新增"知识库"。布局以原型 `prototypes/knowledge-base.html` 为准,三栏:

**A. 浏览/检索知识(最高频)**
1. 左栏「知识库库」:分「当前项目」+「共享库(可挂载)」两组,库上有 `跟随代码`/`共享` 徽章。
2. 选中库 → 中栏顶部出现"提供给 AI 的知识 = 本项目库 + [已挂载共享库 chips]",下面是页面树 + markdown 正文。
3. 正文里 `[[链接]]` 可点击跳转(支持跨库);底部显示反向链接。

**B. 人工编辑页面**
- 点"编辑" → markdown 文本框 → 保存。保存即落一条 activity(tool=manual,act=edit),可撤销。

**C. 挂载/卸载共享库**
- 在 mounts 条上点共享库 chip 的挂载/卸载;或在左栏共享库上操作。即时生效,改变"提供给 AI 的知识"范围。

**D. 新建知识库**
- 左栏 ＋ → 弹窗选 kind(共享/项目)+ src(人工沉淀/跟随代码)+ 命名 → 创建。

**E. 看 AI 都改了啥 / 撤销**
- 右栏「知识库活动」时间线:每条显示 谁 + 用了哪个 `core.kb.*` 工具 + 改了哪页 + 时间。每条带**撤销**按钮。
- 这是"不审批但可控"的核心体验:人不用事前批,但能随时看 AI 写了什么、一键回退。

**F. 从代码库生成 / 刷新**
- `src=code` 库:页面陈旧时顶部出现琥珀色"陈旧"提示条 + "让 AI 刷新"按钮(触发 AI 调 `core.kb.refresh_from_code`)。
- 库级"从代码库生成"按钮:仅对 `src=code` 库开放,触发 AI 依据代码补全/重建页面。

## 6. wiki 跟随代码机制(陈旧检测 + 刷新)

**不自动改写、不自动归档**——这是本期明确的产品决策。机制是"检测陈旧 → 提示 → 由人或 AI 触发刷新":

1. **陈旧检测**:`src=code` 页面记录 `src_files`(派生自哪些文件)+ `src_fingerprint`(这些文件的指纹/哈希)。当对应源文件变化(指纹不一致),把页面标 `stale=true`。检测触发点由工程师评估(如 commit 事件 / 文件变更信号,本项目已有 `file_changes`、`repo.commit` 事件类别可复用)。
2. **提示**:前端在陈旧页面显示提示条;库里有陈旧页时,库/页节点给 `陈旧` 徽章。
3. **刷新**:人点"让 AI 刷新" → 触发某个 Agent 调 `core.kb.refresh_from_code` → AI 读当前源文件重写该页 → 清 `stale`、更新指纹 → 落 activity(act=refresh,可撤销)。
4. **保护人工编辑**(重要取舍):若某页最近一次写入是 `human`,刷新时**不静默覆盖**,而是提示"此页有人工编辑,确认让 AI 重写?"由人决定。AI 没碰过/纯 code 来源的页面可直接刷新。

> 关键边界:系统**只检测和提示**陈旧,**不自动重写**。重写永远是显式触发(人点按钮或 Agent 明确调工具),与本项目"无自动级联"的架构一致。

## 7. 边界与异常

- **空状态**:新项目只有一个空项目库 → 引导"从代码库生成"或新建第一页。
- **孤儿页**:`create_page` 没入链 → 允许创建但前端/工具警示,索引页给"未链接"分组。
- **断链**:`[[链接]]` 指向不存在的页 → 渲染成"待创建"样式,可点击触发新建。
- **跨库链接目标在未挂载的库**:渲染为不可达,提示"该页在未挂载的库 X 中"。
- **并发编辑**:人正在编辑时 AI 也写同一页 → 以 activity 顺序为准,后写覆盖,但旧版进 `prev_body` 可回退(不做复杂锁)。
- **撤销已被覆盖的写入**:只能回退到该 activity 记录的 `prev_body`,不做多级合并。
- **删除共享库**:若仍被项目挂载 → 提示先卸载或确认级联卸载。
- **权限**:沿用项目可见性(用户只能操作自己项目可见的库);跨项目 shared 库的写入权限由工程师按现有 permission_level 评估。

## 8. 范围(本期做 / 不做)

**做**:多 KB 数据模型(project/shared + manual/code)、挂载多对多、页面 CRUD + wikilink + 反向链接、`core.kb.*` 工具全套、活动日志 + 撤销、陈旧检测 + 提示 + AI 刷新、知识库前端三栏(对齐原型)。

**不做(本期)**:向量检索/RAG;页面历史多版本树(只保留上一版用于撤销);跨页面 AI 自动重构;权限的精细 ACL(沿用现有项目可见性即可);自动定时全量重生成(只做事件触发的陈旧检测)。

## 9. 验收标准

1. 能新建 shared 库和 project 库;每个项目自动有一个 project 库。
2. 共享库能被多个项目挂载/卸载,"提供给 AI 的知识"范围随挂载实时变化。
3. 人能在前端浏览页面、点 `[[wikilink]]`(含跨库)跳转、看反向链接、编辑保存。
4. AI 能调 `core.kb.list/read_index/read_page/search` 检索,调 `create_page/update_page` 写入。
5. 每次写入(AI 或人)都在「知识库活动」出现一条,显示工具来源,且能**撤销**还原。
6. `src=code` 页面在源文件变化后被标 `stale`,前端显示提示,点"让 AI 刷新"后页面被重写、`stale` 清除,且这次刷新可撤销。
7. 人工编辑过的页面被刷新时有二次确认,不被静默覆盖。
8. 索引页能反映库内页面结构,AI 走 index-first 能找到目标页。
