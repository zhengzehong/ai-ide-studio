# 跨项目会话恢复缺陷修复设计

## 问题

项目 A 已选择会话后，切到项目 C 并选择会话，再返回 A，A 的会话选择丢失。项目内切换 Agent 后返回不会丢失。

切回 A 时，A 的会话列表会先激活，但全局 `currentSessionId` 暂时仍指向 C 的会话。Workspace 当前把这个过渡态当作 A 的会话已失效，提前删除 A 的 last-session 映射；后续恢复 effect 因映射已不存在而无法恢复 A。

## 方案

保留现有两阶段流程：先清理不属于当前项目的全局会话，再由恢复 effect 选择目标项目记忆的会话。清理阶段增加一个判定：

- 当前全局会话与目标项目记忆会话不同：属于跨项目过渡，只清空全局会话，不删除目标项目映射。
- 当前全局会话与目标项目记忆会话相同，但不在目标项目会话列表：属于会话真实失效，可以清理该项目映射。

判定放在 Workspace helper 中，保持纯函数并用两个单元断言覆盖。

## 非目标

- 不重构 Session store。
- 不改变消息缓存、WebSocket 订阅或项目列表缓存。
- 不调整项目内 Agent/会话点击行为。

## 验收

- A -> C -> A 后恢复 A 原会话，C 的会话选择也保留。
- 当前项目记忆会话真实删除后，失效映射仍会被清理。
- 相关测试、全量测试、构建、lint 和 diff check 通过。
